# 来源卡与交付索引

在形成关键结论或开始保存素材时读取。使用轻量 Markdown 表格、CSV 或已有项目格式即可，不为一次性调研搭建数据库。字段按实际用途填写；未知写明未知，不捏造日期、身份或原始作者。

## 论据来源卡

每个可独立核查的关键说法使用编号，例如 C001；来源可由多个论据共享。

| 字段 | 内容要求 |
|---|---|
| 研究问题／待核实说法 | 用户输入及需要回答的具体问题；没有稿件时不强制补写口播 |
| 来源编号与性质 | 例如 S001，官方声明／专利方案／原始采访／测试记录／个人观点／媒体转述 |
| 标题、发布者、身份依据 | 姓名或账号、机构；记录为何认定其身份，不能只凭认证徽标 |
| 原始地址与内容标识 | 永久链接、帖子 ID、文档编号；镜像或存档地址另列，不替换原始地址 |
| 日期与版本 | 已知的发布日期、文件版本；另记实际访问日期与时区，不猜发布日期 |
| 原文定位与摘录 | 页码、章节、段落、原文关键词或视频起止时间；仅保留必要短摘录，并附准确转述 |
| 读取与核验状态 | 原文已读／原视频片段已看／仅转录稿／仅二手转述／原文不可访问；标注实际做过的核验 |
| 能支持的内容 | 具体到该来源支持的事实或作者主张 |
| 限制与可用表述 | 估计、条件、尚缺证据、自己的推断；需要口播时提供对应措辞 |
| 关联素材编号 | 例如 A001、A003；没有对应画面时如实标记 |

链接能定位到原文只是来源可追溯的一部分。还需检查发布主体、原文上下文与待核实说法是否匹配。访问受阻时，保留原地址、错误状态和实际读到的替代材料，不能把搜索摘要或转载伪装成原文。

## 素材卡

| 字段 | 内容要求 |
|---|---|
| 素材编号与本地路径 | 例如 A001；文件相对于总目录的路径用于索引，最终回复提供完整可点击路径 |
| 用途与看点 | 论据证据／解释画面／趣味反应，可多选；用一句话说明值得使用的原因 |
| 帖子与原始素材地址 | 发现它的帖子链接；追到原发布处后另记原视频、原图或文档地址 |
| 作者及来源关系 | 原创／转载／二创／归属未确认；必要时记录引用或转发链 |
| 相关论据或主题 | 关联 C001，或直接关联主题；趣味素材无须伪造事实论据 |
| 内容性质及语境 | 实拍、模拟、概念展示、玩笑、个人评价等；有歧义就保留未确认状态 |
| 建议使用位置 | 开头引入、技术解释、网友反应、转场等建议；视频给出值得使用的时间段 |
| 文件质量与衍生关系 | 实际宽高、视频时长及音轨状态等必要信息；原件／抽帧／裁剪／加标注及对应原件 |
| 验证与缺口 | 文件可读、关键画面对上、实际检查方式；无高清原件或出处未找到等具体限制 |

## 一个总目录的组织方式

以下仅为可按内容缩减的示例，不预建空目录：

```text
主题素材总包/
  来源与素材索引.md
  01_论据证据/
  02_演示视频/
  03_图片与结构图/
  04_观点与趣味素材/
  05_剪辑衍生素材/
```

文件名建议“素材编号_发布者_简短内容_质量或时间段”，帖子 ID 可保存在索引中。保存原始文件后再生成裁剪或片段，不覆盖原件。批量复用旧文件时使用清单确认是否缺失；哈希可辅助识别相同文件，不把哈希等同于内容真实性证明。

## 典型判断

- 官方原帖描述风扇抽气，公开专利描述低压区域：可分别记录官方主张与技术方案；不能据此推断该产品完整配置已与专利所有实施例一致。
- 网友发布倒挂画面并配玩笑：保留该帖作为网友反应，再追画面的原始发布会。画面出处未找到时，明确记录缺口。
- 采访转录写“每个可能约 20 千瓦”：保留估计含义；只核对转录就记录为转录核验，待听看原视频后再更新状态。
- 官网原帖的三个截图：可以有三个素材编号，仍对应一个来源编号。
