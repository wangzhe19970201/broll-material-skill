# 高清取材与原件验证

在截图、视频下载、抽帧和查找画面原始出处时读取。具体工具和参数依照 Agent Reach 对应平台 reference 与当前帮助，不把历史登录状态或旧命令写成前提。

## 先识别内容，再获取文件

- 读取用户指定帖子，核对返回的帖子 ID、发布者、正文与附件。线程读取可能先给父帖，下载工具也可能包含引用帖或回复附件，需逐项确认归属。
- 网友转发中的画面，可沿原发布者、引用关系、画面标识、字幕、仪表读数、背景与拍摄角度查原视频。单靠视觉相似只能判为候选。
- 长视频可先稀疏抽帧定位区间，再在候选区间细查，保留匹配时间码与同一画面的多项特征。无需把全部长视频密集抽帧。
- 保存网页、原帖或文档的来源信息时，区分内容原始地址与临时下载 CDN 地址；后者不能单独承担长期引用用途。

## 图像与截图

- 已有原图、官方图或文档原件时优先获取原文件。X 图片可检查实际公开的原图规格；服务器没有提供的细节不能通过放大创造。
- 帖子证据需真实渲染页面；搜索摘要、阅读器纯文本、重排卡片不能冒充原帖截图。原页面无法渲染时，说明当前只取得文字证据或替代展示。
- 高清由文字可读、图片实际像素与保留信息判断；大尺寸视口或输出文件名中的“4K”不证明清晰度。
- 优先用合理视口、设备像素比和浏览器缩放取得可读画面。保留含来源身份与正文的证据版，另存适合视频展示的裁剪版。
- 不改正文、账号、日期、徽标或图表数据。若为展示调整布局或加标注，记录处理方式，保留未经调整的证据版；不得让编辑产生错误归属或遗漏关键限定。
- 技术图保留文档编号、图号或页码的对应关系。只取得媒体转载的专利图，就标明文件来自转载，并另列专利地址；未取得完整文档时不宣称全套已下载。
- 不用 AI 重绘或补细节后的图片充当原始证据。原件分辨率有限时明确限制。

## 视频

- 查询实际提供的格式，按用户需要选择最高有用质量并保留音轨；不能直接把搜索缩略视频当最高画质。素材没有音轨时如实记录。
- 下载完成、合并／封装进程退出、最终文件落盘后，再读取验证。不要在最终改名或封装仍进行时启动占用文件的解码任务。
- 核对实际分辨率、时长、编码等必要媒体信息；抽取或播放关键片段，确认是目标画面。长视频、下载异常或交付完整回放时，按风险增加完整解码检查。
- 如实区分“元数据读取通过”“关键片段已看”“全片解码通过”和“播放器实际播放通过”，不要相互替代描述。
- 默认保留取得的原始文件。为剪辑生成片段时，标明原视频、起止时间和是否重编码；用户只要求下载时不擅自制作完整剪辑项目。
- 同一视频出现在多个帖子里时，文件可以去重，帖子配文及来源关系仍分别保留。

## 失败与交付

- 遇到 403、429、登录失效或媒体不可下载，按平台 reference 的恢复路线处理。确定性失败不原样重试，不能把另一篇类似内容当成指定原文。
- 正文读到了但截图未取得、视频地址找到了但文件未下载、字幕取得了但原音未核对，分别记录。
- 交付前逐项检查索引、原始地址、文件和目标内容能对上。保留原件、来源与衍生关系；停止在已授权的交付范围内。
